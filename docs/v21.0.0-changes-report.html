1. 上下文：为什么做这次变更

项目画像：听风AI 是已上生产的 AI 网关（https://imagefree.hwhcie.bond，Azure），聚合 imagefree.net / aifreeforever.com / tryingopen 上游，统一暴露 OpenAI 风格 /v1/*；含 AI 工具门户（Vue3）、React 站长后台、Agent DAG 编排、MCP、桌面版。上一轮（v20.3.x）已完成门户重构、nginx 静态加速、DAG explain 教学化、数据备份闭环、CI 修复。

触发点：全面审计发现 14+ 真实缺口——版本号漂移（api 20.3.10 ≠ git HEAD 20.3.11，e2e 契约甚至停留在 20.0.0）、前端 i18n 差 1 页（DLQ）、landing 有 sw.js 却不可安装（缺 manifest/icon）、litestream 秒级备份建而未启、测试隔离债、前端包体积未验证、旧产物残留等。

方法论：按 Spec-Kit 7 阶段（constitution → spec → plan → tasks）先建规范，再真实落地——每项带验收命令与证据，非烧钱链路全部真跑验证，外部受限资源（R2/Grafana/UptimeRobot）诚实标注"待授权/待验证"。随后启动独立审查线程六维复核，主线程修复后复验闭环。

2. 直觉：核心命题

v20 解决了"门户形态 + 生产加固 + 教学化"，v21 的主线是「一次调用即跑通 + 数据抗毁 + 移动原生 + 运维闭环」：

  • 版本门禁：不再靠人肉检查发版——一条命令全链同步 + CI 首步测试 fail-fast，漂移自动红。
  • 移动原生：landing 已有 SW 缓存与注册，只差 manifest/图标/安装提示就能"添加到主屏幕"——不重写既有 SW（三策略正确），只在既有轮子上补 installability。
  • 数据抗毁：VACUUM INTO 每日全量已闭环；litestream sidecar 在 compose 里已定义，本期补凭证位 + 本地 type:local 验收路径，RPO 随时可降到秒级。
  • 不重复造轮子：compose obs/backup profile、vite manualChunks、sw.js、_pkg_attr 契约——全部复用既有资产，只做"启用 + 验证"。
  • 诚实披露：R2 真上传、Grafana Cloud、UptimeRobot 账户是外部资源，文档化路径、标 L2 授权，不伪装启用。

6. 变更测验（你必须通过）

以下 10 题覆盖本次全部关键变更。点击每题展开答案，请先自行作答再核对。

Q1：版本号从 20.3.10 统一到多少？用什么工具完成？

✅ 21.0.0。用 python scripts/sync_version.py --set 21.0.0（幂等全链同步 9 文件 + e2e_v12 契约断言）。

Q2：版本漂移靠什么在 CI 首步被拦截？

✅ tests/test_version_consistency.py——全链文件存在 + semver + 全链相等 + e2e 契约一致四层断言，任一文件缺/漂移即红。

Q3：e2e_v12.py 里版本契约断言最初卡在哪个值？为什么卡住？

✅ 硬编码 20.0.0（落后真实 20.3.10）。根因是版本全链无自动化门禁，发版靠人肉检查漏项。

Q4：管理端 15 个页面中，v21 收尾补的是哪一页的 i18n？补了几个 key？

✅ DLQ（死信队列）页，补 dlq.* 25 个 zh/en 平行 key；由 isLangComplete() 断言锁定一致性。

Q5：landing 之前"有 SW 但不可安装"，缺的三样东西是什么？

✅ manifest.webmanifest、192/512（及 180）图标、beforeinstallprompt 安装提示组件。SW 本身已存在且三策略正确，未重写。

Q6：manifest 的 theme_color 为什么必须是 #0a0e1a？

✅ 必须与 landing/index.html 的 theme-color meta（L41-42）一致，否则 PWA 安装界面颜色与站点不同步；已加双源注释锁定。

Q7：PwaInstallPrompt.vue 中 iOS Safari 如何触发安装提示？

✅ iOS 无 beforeinstallprompt → 用 navigator.standalone 检测 + 静态"分享→添加到主屏幕"提示；Chrome/Edge/Android 走 beforeinstallprompt。

Q8：独立审查线程在 v21 批次抓到哪两个阻塞缺陷？

✅ B1：PwaInstallPrompt 的 appinstalled 匿名监听器永不卸载（移除的是不相干引用）；B2：uptime_probe 成功路径打印 ✅ 在 Windows GBK 终端崩溃。

Q9：uptime_probe.py 修复 B2 的做法是什么？

✅ main() 开头 sys.stdout/stderr.reconfigure(encoding="utf-8", errors="replace")（与 sync_version.py 同法），GBK 终端不再崩溃。

Q10：litestream 秒级备份本期"真实完成"到哪一步？剩最后一步是什么？

✅ 已完成：compose backup profile 确认、.env.production.example 凭证位补齐、SOP 启用/验收/恢复命令文档化、本地 type:local 验收路径。剩：填 R2 真凭证 + docker compose --profile backup up -d（L2 授权）。
