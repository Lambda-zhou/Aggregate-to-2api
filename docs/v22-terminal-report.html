1. 上下文：为什么做这些变更

项目画像：听风AI 是已上生产的 AI 网关（Azure，公益开放），聚合 imagefree.net / aifreeforever.com / tryingopen 上游，统一 OpenAI 风格 /v1/*。含 AI 工具门户（Vue3）、React 站长后台、Agent DAG 编排、MCP、桌面版、PWA。

起点：v20.3.x 已完成门户重构、nginx 加速、DAG explain、数据备份闭环。全量审计发现 14+ 缺口：版本漂移（api 20.3.10 vs git 20.3.11，e2e 契约停在 20.0.0）、i18n 差 1 页、PWA 不可安装、litestream 建而未启、测试隔离债等。

方法论：Spec-Kit 7 阶段规范 → 真实落地（每项带验收命令）→ 独立审查线程六维复核 → 修复 → 复验闭环。烧钱链路（真实图片/视频生成）Mock 覆盖；外部资源（R2/Grafana/UptimeRobot）文档化路径标 L2 授权。

2. 直觉：核心命题

  • 一次调用即跑通：版本门禁 CI 首步 fail-fast，漂移自动红；调用者按 README 最少步骤可用。
  • 不重复造轮子：复用 compose obs/backup profile、vite manualChunks、既有 sw.js、_pkg_attr 契约——只做"启用 + 验证"。
  • 诚实披露：R2 真上传、Grafana Cloud、UptimeRobot 账户标「待验证/L2 授权」，不伪装启用。
  • 测试防伪：独立审查抓到 H1 伪测试（generator 429 分支零覆盖）→ 改真端到端；config 双向校验盲区误报 10 个合法消费 → 扩展扫描暴露 8 个真实模板缺口。

10 题覆盖全部关键变更，请先自答再展开核对。

Q1：三个发布版本各自核心是什么？

✅ v21 基座（版本门禁/i18n/PWA/SEO）+ v22 生产收益（SSE 保护/CI 门禁/脚本单测）+ v22.0.1 审计修复（config 盲区/H1 伪测试）。

Q2：版本漂移靠什么在 CI 首步拦截？

✅ test_version_consistency.py（文件存在+semver+全链相等+e2e 契约四层），ci.yml 单测首步 fail-fast。

Q3：SSE 连接上限如何配置？缺省值多少？

✅ IF_SSE_MAX_CONNECTIONS（0=不限制，缺省关向后兼容）；超限 subscribe 抛 ConnectionError，generator/WS 产出 429。

Q4：uptime_probe 对 503 与网络错误如何区分？

✅ 503 返回真实状态码（HTTPError 分支）；连接失败/超时/DNS 返回 -1（OSError 分支）。

Q5：config 双向校验测试修复了什么盲区？

✅ _config_consumed 原只扫 config 包，误报 email_sources/prompts/vector 等直接 os.getenv 的 10 个合法消费为孤儿；扩展至整个 api/ 后暴露并补 8 个真实模板缺口。

Q6：H1 伪测试的缺陷是什么？如何修复？

✅ generator 429 用例用 se.FakeRequest（不存在）恒走退化分支，429 分支零覆盖；改用测试本地 FakeRequest 真端到端驱动，断言 event: error。

Q7：前端 i18n 覆盖到什么程度？

✅ 管理端 15/15 页面双语（DLQ 页 v21 收尾，25 key 平行），isLangComplete() 断言锁定 zh/en 一致。

Q8：PWA 为什么没重写 sw.js？

✅ 既有 sw.js 三策略正确（静态 Cache-First/API Network-First/字体 SWR），只补 manifest/图标/安装提示（installability），预缓存加 manifest+图标，CACHE_NAME 升版。

Q9：独立审查在 v22 抓到什么真实问题？

✅ H1 伪测试（generator 429 分支零覆盖）+ config 双向校验盲区（10 个合法消费误报孤儿、8 个真实模板缺口）。均已修复并验证。

Q10：三个 Release 的 id 是什么？
